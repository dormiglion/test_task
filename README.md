# Тестовое задание: инвентарь и предметы

## Описание

Серверная модель системы инвентаря и предметов на **Node.js + TypeScript**, без внешних зависимостей.

Игроки могут:

* получать предметы;
* выбрасывать предметы на землю;
* подбирать предметы, находящиеся рядом;
* использовать предметы с различным поведением.

Мир работает по системе **тиков (tick)**: предметы на земле живут ограниченное число тиков и удаляются автоматически, а эффекты предметов применяются к игрокам на каждом тике.

## Запуск

Требуется Node.js 22 или новее.

Установить зависимости:

```bash
npm install
```

Запустить демонстрацию:

```bash
npm start
```

Прогнать тесты:

```bash
npm test
```

Обе команды сначала собирают проект (`tsc`), отдельно вызывать сборку не нужно.

## Что показывает `npm start`

Шесть сценариев, каждый печатает ход выполнения:

1. выброс предмета и подбор его другим игроком, включая отказ по расстоянию;
2. исчезновение предмета с земли по истечении времени жизни;
3. использование предмета и изменение состояния игрока;
4. одновременный подбор одного предмета тремя игроками — успешным оказывается ровно один;
5. бинт: лечение растянуто на несколько тиков, затем эффект спадает;
6. оружие: экипировка, выстрел, перезарядка патронами, снятие оружия.

## Тесты

Используется встроенный тест-раннер Node (`node --test`), внешних библиотек нет.

```bash
npm test
```

86 тестов в шести файлах:

| Файл | Что покрывает |
|---|---|
| `required.test.ts` | сценарии, обязательные по заданию |
| `ground.test.ts` | земля: радиус подбора, позиция, границы времени жизни |
| `inventory.test.ts` | выдача предметов, стаки, выброс |
| `items.test.ts` | поведение каждого типа предмета, эффекты по тикам |
| `players.test.ts` | жизненный цикл игрока, перемещение, восстановление из хранилища |
| `weapons.test.ts` | экипировка, стрельба, перезарядка |

Файл `required.test.ts` вынесен отдельно: в нём ровно те четыре сценария, которые задание требует показать обязательно — drop → pickup, исчезновение по таймауту, эффект `use`, конкурентный подбор. Логи игры в нём не глушатся, поэтому по выводу видно каждый шаг.


### Запуск части тестов

Один файл:

```bash
node --test dist/tests/ground.test.js
```

Тесты, в названии которых встречается подстрока:

```bash
node --test --test-name-pattern="брон" "dist/tests/*.test.js"
```

Обе команды работают по уже собранному `dist`, поэтому перед ними нужно хотя бы раз выполнить `npm run build`.

## Архитектура

* **GameWorld** — ядро системы: игровой API, тики, единственная точка доступа к состоянию мира.
* **Player** — состояние игрока и логика работы с инвентарём.
* **Items** — иерархия предметов, наследующихся от `BaseItem`.
* **InventoryStorage** — асинхронный слой хранения, имитирующий внешнюю БД с настраиваемой задержкой.
* **IInventoryStorage** — контракт хранилища: ядро зависит от интерфейса, а не от конкретной реализации.
* **ItemFactory** — реестр типов предметов и фабрика экземпляров по сохранённому состоянию.
* **EffectRegistry** — реестр эффектов, действующих во времени.

Ядро не знает о конкретных типах предметов и эффектов: и то и другое регистрируется само и достаётся из реестра по строковому имени.

Состояние предмета хранится на самом предмете, а не дублируется на игроке. Поэтому патроны в оружии и прочность брони переживают переподключение автоматически — их восстанавливает фабрика вместе с предметом.

## Конфигурация

Все игровые величины вынесены в `src/core/GameConfig.ts`:

* `maxHealth`, `maxArmor` — пределы характеристик игрока;
* `medkit_healing` — сколько восстанавливает аптечка;
* `bandage_healing`, `bandage_duration_ticks` — сила и длительность эффекта бинта;
* `pickupRadius` — радиус подбора предметов;
* `itemLifetimeTicks` — время жизни предмета на земле;
* `mapBounds` — границы карты.

Задержка хранилища задаётся отдельно, при создании: `new InventoryStorage(100)`. В тестах она равна нулю.

## Как добавить новый тип предмета

Ядро при этом не меняется:

1. создать класс-наследник `BaseItem` в `src/items/`;
2. реализовать `use` и, если у предмета есть свои поля, переопределить `getState`;
3. в конце файла вызвать `registerItemType('имя_типа', Класс)`;
4. добавить импорт файла в `src/items/index.ts`.

Если предмет действует во времени, его обработчик регистрируется там же через `registerEffect` — так сделан `bandage`.

## Игровой API

| Метод | Назначение |
|---|---|
| `addPlayer(id, x, y)` | подключить игрока, восстановив его вещи из хранилища |
| `removePlayer(id)` | отключить от игры, вещи остаются в хранилище |
| `deletePlayerFromDB(id)` | удалить данные игрока насовсем |
| `movePlayerTo(id, x, y)` | переместить игрока по карте |
| `giveItem(id, type, amount?)` | выдать предметы с учётом размеров стака |
| `dropItem(id, itemId)` | выбросить предмет на землю |
| `pickUpItem(id, groundItemId)` | подобрать предмет рядом |
| `useItem(id, itemId)` | использовать предмет |
| `equipWeapon(id, itemId)` / `unequipWeapon(id)` | экипировать и снять оружие |
| `useWeapon(id)` / `reloadWeapon(id)` | выстрелить и перезарядить |
| `unequipArmor(id)` | снять броню |
| `getInventory(id)` | инвентарь игрока (копии состояний) |
| `getGroundItems()` | предметы на земле (копии состояний) |
| `tick()` | шаг времени: убрать истёкшие предметы, применить эффекты |

## Осознанные решения и ограничения

* Аптечка расходуется даже при полном здоровье.
* Броня надевается через `use`, а снимается отдельным методом — как и оружие.
* Патроны через `use` заряжают экипированное оружие; отдельного запаса патронов у игрока нет.
* Система урона не реализована — задание её не требует, поэтому броня не расходуется.
* Обработчики `onPickup` и `onDrop` не заведены: ни одному из реализованных предметов они не нужны.
